# Bdoapi

[![CI status](https://github.com/nicolaspaillard/Bdoapi/actions/workflows/docker-publish.yml/badge.svg?branch=main)](https://github.com/nicolaspaillard/Bdoapi/actions/workflows/docker-publish.yml)

[![Docker Pulls - bdoapi-dev](https://img.shields.io/docker/pulls/nicolaspaillard/bdoapi-dev?style=flat-square)](https://hub.docker.com/r/nicolaspaillard/bdoapi-dev)

Bdoapi is a Go service that regularly collects data about Black Desert Online (pearl shop outfits and pets from the market API, and in-game events scraped from the official site), stores it in PostgreSQL and exposes it through a REST API.

## Endpoints

| Endpoint                                | Description                                            |
| --------------------------------------- | ------------------------------------------------------ |
| `GET /outfits?date=YYYY-MM-DD HH:MM:SS` | Pearl outfits sales and preorders since the given date |
| `GET /pets?date=YYYY-MM-DD HH:MM:SS`    | Pearl pets sales and preorders since the given date    |
| `GET /events`                           | Current events with their end date                     |

Data is refreshed every hour (every 5 minutes after a failed update).

## Project structure

```
.
├── main.go                  # entry point
├── internal/
│   ├── config/              # environment variables, database connection string
│   ├── server/              # migrations, updater loop, HTTP server
│   ├── pearl/               # outfits and pets (market API)
│   └── events/              # events scraper (Chromium via rod)
├── db/                      # code generated by sqlc
├── sqlc/
│   ├── migrations/          # SQL migrations (goose)
│   └── queries/             # SQL queries (sqlc)
├── sqlc.yaml
├── Dockerfile               # production image
├── Dockerfile.dev           # development image (live reload with air)
├── docker-compose.yml
└── example.env
```

## Docker images

- [nicolaspaillard/bdoapi:latest](https://hub.docker.com/r/nicolaspaillard/bdoapi) — production image.
- [nicolaspaillard/bdoapi-dev:latest](https://hub.docker.com/r/nicolaspaillard/bdoapi-dev) — development image.

## Continuous integration (CI)

The workflow in `.github/workflows/docker-publish.yml` runs with **GitHub Actions**:

- On every pull request to `main`, both images are built (no publishing).
- On every push to `main`, both images are built and published to Docker Hub with the `latest` tag.

See the [Actions page](https://github.com/nicolaspaillard/Bdoapi/actions/workflows/docker-publish.yml) for details.

## Prerequisites

- Docker & Docker Compose
- For local development without Docker: Go, Chrome or Chromium (used by the events scraper), and [sqlc](https://sqlc.dev) to regenerate `db/`

## Environment variables

| Variable      | Default     | Description       |
| ------------- | ----------- | ----------------- |
| `DB_USER`     | `postgres`  | Database user     |
| `DB_PASSWORD` | `password`  | Database password |
| `DB_HOST`     | `localhost` | Database host     |
| `DB_PORT`     | `5432`      | Database port     |
| `DB_NAME`     | `bdoapi`    | Database name     |
| `PORT`        | `8081`      | HTTP port         |

## Quick start with Docker Compose

1. Copy the example file and edit it:

   ```sh
   cp example.env .env
   ```

2. Start the services:

   ```sh
   docker compose up --build
   ```

   This starts:
   - `database` (PostgreSQL, port 5432)
   - `backend` (production image, port 8080)
   - `backend-dev` (development image, port 8081, mounted volume)

3. Stop the services:

   ```sh
   docker compose down
   ```

> Ports are only exposed internally by default. To reach a service from outside, add `ports:` in `docker-compose.yml`.

## Manual start

Run from the project root, because migrations are loaded from `./sqlc/migrations`:

```sh
go run .
```

## Database

- Migrations run automatically at startup.
- After changing files in `sqlc/queries/` or `sqlc/migrations/`, regenerate the Go code with:

  ```sh
  sqlc generate
  ```
